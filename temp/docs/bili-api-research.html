接口长什么样

列表接口

GET https://show.bilibili.com/api/ticket/project/listV2
?version=134&page=1&pagesize=20
&area=110000
&filter=
&platform=web
&p_type=展览

area 必填，是六位国标行政区划码，例如北京 110000、朝阳区 110105、南京 320100。上游的 area.ts 正是汉字地区名到此码的映射表。

p_type 是“从哪个 B 站频道拿数据”，合法值为 展览、演出、本地生活；不传时得到混合列表。它不是“漫展/演唱会”这种具体体裁。

详情接口

GET https://show.bilibili.com/api/ticket/project/getV2
?version=134&id=<project_id>&project_id=<project_id>&requestSource=pc-new

列表接口里的 guests[].name 实测通常为空；详情接口才有嘉宾姓名、介绍、预约数和头像。因此详情页需要额外请求一次。

频道与体裁不是同一个概念

展览频道

主要返回：漫展、IP展览、其他展览。

演出频道

主要返回：演唱会、音乐会、livehouse、话剧、音乐剧、音乐节、其他演出。

已验证的限制

  • filter=东方 与空 filter 返回项目 ID 是否完全相同：是，服务端过滤无效。
  • page=1 与 page=2 返回项目 ID 是否完全相同：是，不能依赖分页；接口声称的总数从 21 变成 41。
  • pagesize=30：HTTP 200，接口消息：请求非法，请稍后重试。
  • 因此要提高大城市覆盖率，只能按区县拆分查询、按 project_id 去重。插件将把它做成默认关闭的 --fanout / 管理台开关，而不是伪分页。

建议的 Koishi 设计（未实施草图）

保留现有 漫展（allcpp 关键词查询）完全不动，新增独立的 B 站地区查询命令族：

漫展B 查询 北京
漫展B 图片查询 南京
漫展B 查询 广州 --scope 演出
漫展B 查询 成都 --scope 全部
漫展B 查询 北京 --fanout
漫展B 订阅 上海
漫展B 一键查询 --scope 本地生活

--scope 的含义：漫展 = 展览 + 混合（保留漫展/Only/IP/其他展览）；展览、演出、本地生活 各取一个频道；全部 取四个频道且不按体裁过滤。省略时读取管理台默认值。

订阅只保存地区码，按已选方案始终跟随管理台当前默认范围；一键查询 --scope 仅本次覆盖，不修改订阅或默认配置。新订阅表与 allcpp 表分离，避免破坏旧订阅。

图片查询复用现有 Puppeteer 能力，但增加 B 站主题：蓝 #00A1D6、粉 #FF5687，且页脚写明“数据来源：B站会员购”。

用户看见的命令结构

核心原则：数据源用根命令区分，用户行为用第二层区分；范围是一次查询的筛选条件，因此放在 option，不再堆第三层子命令。

漫展                         现有 allcpp 数据源，保持原样
  ├─ 查询 <关键词>
  ├─ 图片查询 <关键词>
  ├─ 一键查询 / 一键图片查询
  └─ 订阅 / 取消订阅 / 订阅列表

漫展B                        新增 B站会员购数据源，只接受地区
  ├─ 查询 <地区> [--scope <范围>] [--fanout]
  ├─ 图片查询 <地区> [--scope <范围>] [--fanout]
  ├─ 一键查询 [--scope <范围>] [--fanout]
  ├─ 一键图片查询 [--scope <范围>] [--fanout]
  └─ 订阅 <地区> / 取消订阅 [地区] / 订阅列表

例如“东方”“原神”是主题关键词，应该使用现有 漫展 查询 东方；B 站接口没有可靠关键词检索，漫展B 查询 东方 会明确提示“B站查询只支持行政区，例如北京、南京、朝阳区”。

模拟帮助：用户输入 漫展B --help

漫展B - B站会员购地区活动查询与订阅

用法：漫展B <子指令>

子指令：
  查询 <地区>                 查询一个地区的 B站会员购活动
  图片查询 <地区>             将查询结果渲染为图片（需要 Puppeteer）
  一键查询                    查询本频道已订阅的所有地区
  一键图片查询                将所有订阅结果渲染为图片（需要 Puppeteer）
  订阅 <地区>                 订阅一个地区
  取消订阅 [地区]             取消一个地区，省略地区则取消全部
  订阅列表                    查看已订阅地区

范围说明：
  默认范围由管理员在 Koishi 控制台设置。
  单次查询可使用 --scope 临时覆盖默认范围。
  可选范围：漫展、展览、演出、本地生活、全部、自定义。

示例：
  漫展B 查询 北京
  漫展B 查询 广州 --scope 演出
  漫展B 订阅 南京
  漫展B 一键查询 --scope 本地生活

输入「漫展B 查询 --help」查看查询选项。

模拟帮助：用户输入 漫展B 查询 --help

漫展B 查询 <地区> - 查询 B站会员购中的地区活动

用法：漫展B 查询 <地区> [选项]

参数：
  <地区>                       行政区名称，例如北京、南京、朝阳区

选项：
  -s, --scope <范围>          仅本次覆盖控制台默认范围
                                漫展：展览 + 混合，保留漫展/Only/IP/其他展览
                                展览：只查询展览频道
                                演出：只查询演出频道
                                本地生活：只查询本地生活频道
                                全部：查询全部频道，不按体裁过滤
                                自定义：使用控制台的高级自定义规则
  -f, --fanout                 按区县展开查询，提高大城市覆盖率
  -h, --help                   显示帮助

示例：
  漫展B 查询 北京
  漫展B 查询 南京 --scope 漫展
  漫展B 查询 上海 --scope 全部
  漫展B 查询 北京 --fanout

未指定 --scope 时，使用管理员设置的默认范围。
为什么没有 漫展B 演出 查询 北京 这种三级命令？因为“演出”只是同一次查询的范围，而不是独立功能。用 --scope 演出 能保持帮助列表稳定在 7 个 B站子指令，而不是把每个行为复制成 5 份。

订阅体验与默认范围

按当前规划，订阅只保存“用户 + 会话/频道 + 地区码”，不保存 --scope。原因是你已选择“订阅始终跟随控制台默认范围”。

管理员在控制台把默认范围从「漫展」改为「演出」
              ↓
用户此前执行过：漫展B 订阅 北京
              ↓
用户现在执行：漫展B 一键查询
              ↓
Bot 按「演出」范围查询北京，而不是旧的「漫展」范围

因此 漫展B 订阅 北京 --scope 演出 不注册为合法用法，避免用户以为它会保存演出范围。允许 漫展B 一键查询 --scope 本地生活，但该参数只覆盖这一轮，不改订阅、不改控制台默认值。

订阅表应独立命名为 anime_convention_bili，从而完全不触碰 allcpp 的 anime_convention 关键词订阅。

Koishi 控制台：建议的 B站设置

新增一个独立分组“B站会员购设置”。现有 allcpp 后端、图片、消息和调试设置保持不变。

启用 B站命令　开关，默认开启。关闭时不注册 漫展B 命令；现有 漫展 不受影响。适合不想让机器人请求 B站的管理员。
默认查询范围　单选：漫展（默认） / 展览 / 演出 / 本地生活 / 全部 / 自定义。用户未写 --scope 时使用；所有 B站订阅的一键查询也使用它。
区县展开查询　开关，默认关闭。开启后可查到超过单次 20 条上限的结果；单次查询会更多、更慢，且可能更容易触发 B站限制。
最多展示结果　数字输入，默认 50，建议范围 1～100。统一用于文字和图片结果；按开始日期排序后截断，避免超长消息或超高图片。
自定义请求频道　多选：展览 / 演出 / 本地生活 / 混合。仅当“默认查询范围”选为“自定义”时生效。B站不接受任意自定义频道名称，因此不提供频道自由文本框。
自定义保留体裁　多选已知体裁 + 附加体裁表。已知项包括漫展、Only同人展、IP展览、其他展览、演唱会、音乐会、livehouse、主题餐厅等；附加体裁表使用“名称 | 启用”两列，处理 B站未来新增分类。
图片渲染　复用现有 Puppeteer 图片开关与格式质量设置。B站结果自动选择蓝 #00A1D6、粉 #FF5687 主题及 B站会员购页脚；不额外增加颜色配置，避免控制台堆满样式选项。

高级“自定义”字段会始终出现在配置页并注明生效条件，而不是尝试做 Koishi Schema 当前不支持的动态显隐。
